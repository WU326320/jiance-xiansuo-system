# 启动与环境

这份说明给第一次在自己电脑上部署「监测线索系统 1.0」的同事使用。步骤都对照了仓库里的 `README.md`、启动脚本和配置，文档面向 Windows 10；Windows 11 未在本说明中单独验证。若本机已安装 Python 3.13 且浏览器路径正确，可按相同步骤操作。

仓库是私有的：https://github.com/WU326320/jiance-xiansuo-system
请先向仓库管理员要访问权限，再克隆。不要把别人电脑上的浏览器登录资料、数据库或 `.venv` 拷过来用。

## 1. 运行前置

请先在本机准备好：

- **Git**
- **Python 3.13**（64 位）。采集依赖已按 Windows + Python 3.13 核对过官方 wheel；其他版本未在本说明中验证。安装后，命令行执行 `py -3.13 --version` 应能看到 3.13。
- **Microsoft Edge 或 Google Chrome**。当前仓库里的 `crawler/config/windows.yaml` 把 `browser.chrome_executable` 写成了：

  `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`

  这是原开发机上的路径。如果本机 Edge 不在这里（例如装在 `C:\Program Files\Microsoft\Edge\Application\msedge.exe`），先改这个配置再登录采集平台。也可以改成本机 `chrome.exe` 的完整路径。
- 采集使用本机浏览器的 CDP 模式，三个平台占用调试端口：**淘宝 9222、京东 9223、1688 9224**。启动登录或采集前，请确认这些端口没有被其它程序占用。
- 不需要执行 `playwright install`。Windows 配置里三个平台都是 CDP，连接的是本机 Edge/Chrome；`crawler/requirements.txt` 里的 Playwright 只是 Python 包，不会去下载 Playwright 自带浏览器。

工作台是同一个 Python 服务提供的网页，没有单独的前端构建步骤，也不需要 Node.js 才能运行（Node 只用于仓库里的前端交互测试）。

## 2. 克隆仓库

打开 **普通的** PowerShell（不要用「以管理员身份运行」），先进入自己的用户目录，再克隆：

```powershell
cd $HOME
git clone https://github.com/WU326320/jiance-xiansuo-system.git
cd jiance-xiansuo-system
```

这样项目会装在 `C:\Users\你的用户名\jiance-xiansuo-system`。注意两点：

- 不要照抄别人的盘符（例如 `cd D:\`）。很多电脑没有 D 盘，这一步失败后命令会留在当前目录继续执行。
- 管理员 PowerShell 默认停在 `C:\Windows\System32`，在那里克隆会把项目装进系统目录，之后删除也需要管理员权限。克隆前先用 `pwd` 确认当前目录不是 `C:\Windows\System32`。

后面所说的「项目根目录」就是这个 `jiance-xiansuo-system` 文件夹。

## 3. 创建虚拟环境并安装依赖

本项目需要 **两个** 虚拟环境，不要混用：

| 位置 | 用途 | 启动时如何被用到 |
|---|---|---|
| `backend\.venv` | 工作台和后端（判定、数据库、导出、邮件） | 根目录 `启动工作台.bat` **优先**使用 `backend\.venv\Scripts\python.exe` |
| `crawler\.venv` | 淘宝 / 京东 / 1688 采集 | 工作台发起采集时，后端会 **优先**调用 `crawler\.venv\Scripts\python.exe` |

`workbench/requirements.txt` 本身没有额外运行时包，工作台依赖已包含在 `backend/requirements.txt` 中，不必再单独建一个工作台环境。`export` 的主要依赖（`openpyxl`、`Pillow`、`PyYAML`）也已写在后端依赖里。

在项目根目录执行：

```bat
py -3.13 -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install --upgrade pip
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt

py -3.13 -m venv crawler\.venv
crawler\.venv\Scripts\python.exe -m pip install --upgrade pip
crawler\.venv\Scripts\python.exe -m pip install -r crawler\requirements.txt
```

如果 `启动工作台.bat` 找不到 `backend\.venv`，会退回到 `crawler\.venv`，再没有才用系统里的 `python`。系统 Python 通常没装项目依赖，不建议当作日常启动方式。

默认配置已经指向本项目内的路径。只有需要改监听地址或端口时，才把 `workbench/config/workbench.example.yaml` 复制为 `workbench/config/workbench.yaml` 再修改。没有这份正式配置文件也可以启动。

## 4. 首次启动工作台

双击项目根目录的 `启动工作台.bat`。也可以在项目根目录用：

```bat
backend\.venv\Scripts\python.exe -B -X utf8 utils\start_project.py
```

或（与工作台 README 一致）：

```bat
backend\.venv\Scripts\python.exe -m workbench serve --open
```

- 地址：`http://127.0.0.1:8765/`
- 默认只监听本机 `127.0.0.1`，端口 **8765**
- 第一次启动会在本项目内初始化空数据库，不会带上别人的账号或线索
- 请先打开 `http://127.0.0.1:8765/setup`，设置唯一主管密码（至少 8 位，需同时包含字母和数字）。**只有本机**可以做这次初始化，系统不带预置密码
- 停止服务：在启动用的命令窗口按 `Ctrl+C`
- 不要同时运行两份占用 8765 端口的副本；如果该端口已被占用，先关掉占用的程序再启动

启动失败时，先看启动窗口的退出码，再查看 `workbench\data\logs\workbench.log`。

网页如果还显示旧样式，用 Edge 按 `Ctrl+F5` 强制刷新。

## 5. 登录采集平台

工作台可以先打开，但真正采集前必须在 **这台电脑、这份目录** 里重新登录淘宝（含天猫）、京东和 1688。登录状态写在本副本的 `crawler/profiles/`，不要复制其他电脑或其它副本里的 profile。

在项目根目录执行：

```bat
cd crawler
.venv\Scripts\python.exe -m crawler login taobao --config .\config\windows.yaml
.venv\Scripts\python.exe -m crawler login jd     --config .\config\windows.yaml
.venv\Scripts\python.exe -m crawler login 1688   --config .\config\windows.yaml
.venv\Scripts\python.exe -m crawler check-login all --config .\config\windows.yaml
```

程序会打开对应平台的浏览器窗口，等你自己扫码或输入账号。它不会代填密码，也不会破解验证码或滑块；遇到验证码需要你在页面上完成。Cookie 只留在本机 profile 里。

登录完成后，回到工作台「运行任务」里新建任务即可。日常采集请走工作台，不要直接在命令行里跑完整采集（本说明也不演示这条命令）。

## 6. 配置邮件通知（可选）

没有配置 SMTP 时，任务完成通知只会写到 `workbench\data\logs\workbench.log` 和库里的邮件日志，不会因此报错。

需要发邮件时：

1. 如有必要，先在 `backend/config/rules.yaml` 的 `alert` 节改好 SMTP 主机、端口、发件人和收件人。仓库里目前预填的是原项目的公司邮箱，请改成你们自己要使用的地址。
2. 授权码不要写进任何配置文件，只写入本机 Windows 凭据管理器。在项目根目录执行：

```bat
cd backend
.venv\Scripts\python.exe -m pipeline setup-smtp
```

按提示输入发件邮箱（默认读上面的配置）和授权码（输入不回显，需再输一次确认）。授权码至少 16 位。保存成功后，这条命令会自动发一封测试邮件；也可以再单独执行 `.venv\Scripts\python.exe -m pipeline test-smtp`（同样要在 `backend` 目录、用同一个解释器）。

重新设置授权码时，再跑一次 `setup-smtp` 即可。

## 7. 数据都在本机，不会随 Git 共享

每台电脑、每一份拷贝都是独立的空环境：

- `workbench/data/workbench.db`：账号、邀请、IP 档案、**白名单**、任务、审计和通知记录
- `backend/data/leads.db`：线索和复核记录
- `crawler/profiles/`：各平台登录状态（首次登录后才生成）
- `crawler/out/`、`crawler/logs/`、`crawler/state/`：采集输出、日志和进度

这些目录和数据库已从 Git 忽略，克隆下来是空的。同事之间不会自动共享白名单、账号或线索，需要各自在工作台里维护，或另行约定同步方式。

数据库是本机 SQLite，没有单独的数据库账号密码。管理员密码只在首次初始化时设置。

## 8. 常见问题

**双击启动后立刻退出，或提示找不到模块。**
确认已经按第 3 节建好 `backend\.venv` 和 `crawler\.venv`，并且依赖安装成功。`启动工作台.bat` 若找不到 `backend\.venv\Scripts\python.exe`，会去用 `crawler\.venv` 或系统 `python`，后两者可能没有工作台所需依赖。

**浏览器打不开，或登录/采集报找不到浏览器。**
检查 `crawler/config/windows.yaml` 里的 `browser.chrome_executable` 是否指向本机真实存在的 `msedge.exe` 或 `chrome.exe`。并确认 9222–9224 端口空闲。

**8765 打不开或看到的是另一套系统。**
多半是端口被原项目或另一份副本占用。先关掉占用 8765 的窗口，再重新启动。

**工作台能进，但采集提示未登录。**
必须在当前这份目录里重新执行第 5 节的登录命令，不能复用其它目录的 profile。

**初始化页面打不开或提示无权限。**
主管初始化只允许从本机 `127.0.0.1` 访问 `/setup`。请在运行服务的这台电脑上打开，不要从别的电脑去初始化。

**不想发邮件，任务也能跑完吗？**
可以。未配置 SMTP 时不会阻断任务，只是完成通知留在本地日志里。

**需要让局域网同事用浏览器访问同一套工作台吗？**
默认只监听 `127.0.0.1`。工作台 README 说明：可在 `workbench/config/workbench.yaml` 把 `server.host` 改成本机内网 IP（禁止 `0.0.0.0`），并用防火墙只放行公司网段。本说明未在其它电脑上实际验证这一步。注意：即便改了监听地址，白名单和数据仍然只存在这台电脑的数据库里；这与每人各自克隆、各自维护不是同一件事。
