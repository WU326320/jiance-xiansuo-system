# 监测线索系统 1.0

这是从原项目复制出的独立开发基础版本。后续开发请在本目录进行；原项目保留不动。

## 启动

双击项目根目录的 `启动工作台.bat`。首次启动会初始化本项目自己的数据库；首次使用请在主管初始化页面设置密码。

- 地址：`http://127.0.0.1:8765/`
- 服务端口：8765（本机回环地址）
- 前端：工作台内置原生 HTML/CSS/JavaScript，由同一 Python 服务提供
- 后端及工作台运行环境：`backend\.venv\Scripts\python.exe`
- 采集环境：`crawler\.venv\Scripts\python.exe`
- 停止服务：在启动命令窗口按 `Ctrl+C`

如果8765已被原项目或其他程序使用，请先关闭占用者。不要同时运行两个使用8765的副本。

## 目录

- `workbench/`：网页工作台、API、认证、权限、数据库迁移和界面
- `backend/`：线索判定、规则配置、数据库、主流程和主管理入口
- `crawler/`：淘宝/天猫、京东和1688采集器、配置及离线测试
- `export/`：线索Excel导出
- `project/backend/`：独立商品复核模块
- `prototype/`：已确认玻璃拟态原型及正式版截图
- `doc/`、`需求文档/`、`交付文件/`、`research/`：项目文档和历史交接材料
- `database/`、`project/frontend/`：保留的项目扩展目录
- `utils/`、`wu_tools/`：测试、验收及开发工具

## 独立数据

本副本不包含原账号、任务、线索数据库、采集输出、Windows浏览器登录配置或认证状态。首次启动后，数据只写在本目录：

- `workbench/data/workbench.db`：账号、IP档案、任务、审计和通知记录
- `backend/data/leads.db`：线索及复核记录
- `crawler/profiles/`：首次登录采集平台时按此副本重新创建
- `crawler/out/`、`crawler/logs/`、`crawler/state/`：本副本采集运行后生成

数据库为SQLite，无单独连接账号或密码；管理员密码首次设置，系统不带预置密码。邮件授权码不写入源代码，由Windows凭据管理器另行配置。根目录`config.json`为绑定本机Crow5/MCP绝对路径的代理专用设置，不属于业务运行依赖，故未复制。

## 不限量逐页采集与可选截止

常规采集截止时间可留空：淘宝、京东和1688按完整关键词范围逐页点击分页控件，
直到明确末页或明确无结果。页数、商品数、关键词数、淘宝分段、每日数量和补采数量
均不再截断任务，也没有默认整批运行时限。旧数量配置及 `--max-pages`、
`--limit-keywords`、`--batch` 保留解析兼容，但不再限制采集范围。

只有主动填写未来的截止时间才启用定时持续模式；各平台在同一个截止时间停止发起
新搜索，包括请求间隔和重试等待之后的搜索。已经发出的请求继续解析、逐页保存，
缺失字段和店名等补采按候选逐条处理。全部平台收尾后才提交终态、导出并按配置
发送完成通知，因此实际完成时间可能晚于常规采集截止时间。

请求间隔、单次请求超时、有限异常重试、登录和风控检查继续生效。
未知空页、重复列表、分页异常、登录失效或风控均保留未完成检查点和已有数据，
不能作为已采到末页的证据。空截止时间会覆盖模板中的历史 `run.ends_at`。

新启动的采集子进程自动生效，已启动进程不会热切换。旧批次记录和历史任务保留，
续采依据逐页检查点。实施及验证范围见 [不限量采集实施计划](doc/不限量采集实施计划_20261111.md)。

## 运行测试

### 失败后按页码续采

每页解析成功后，采集器将本页商品和下一页页码一起保存到
`crawler/state/progress/`。失败、登录中断或进程退出后，再次采集相同
IP、关键词范围和平台，会跳过已完成的关键词与页，从失败页继续；
例如第 19 页已保存、第 20 页失败，下次从第 20 页开始。

失败日志会显示已完成页和下次起始页。新任务即使更换日期或输出目录，
也会恢复此前商品到本次输出，避免只保留续采部分。一次范围全部成功后，
该进度关闭，下次视为新一轮；不同平台和关键词范围使用独立进度。
首次启用前的旧任务没有页码检查点，不能凭商品数量反推恢复位置。
请保留 `crawler/state/progress/`，不要在任务运行中清理该目录。

从项目根目录：

```bat
backend\.venv\Scripts\python.exe -B -m pytest workbench\tests -q
node --test utils\workbench-interactions.test.cjs
crawler\.venv\Scripts\python.exe -B -X utf8 utils\workbench_glass_acceptance.py
crawler\.venv\Scripts\python.exe -B -m pytest crawler\crawler\tests -q
```

玻璃版浏览验收使用临时数据库和模拟采集执行器，不连接真实电商平台或发送邮件。实际采集前需在本副本中重新登录各平台。不要把原目录中的浏览器登录profile复制或用于新副本。

初次建立空数据库后，如果需重新运行正式Edge验收，工作台数据库先按其测试流程处理；正式业务数据不要交给验收脚本。
