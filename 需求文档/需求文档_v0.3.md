## 1. 目的
右上角知识产权为委托权利人（葫芦兄弟、黑猫警长、叶罗丽、吾皇等）寻找侵权企业店铺。本系统按需（Xuan 手动启动）从电商平台采集商品，自动初筛、计算金额、按店铺聚合，输出“店铺级线索”Excel；人工只做复核并录入 SaaS。

有效线索三要件（依据公司《右上角侵权线索检索指南》）：
1. 侵权成立（著作权/商标权），并排除合理使用、法定许可、避风港（红旗原则例外）等抗辩；
2. 可估算赔偿金额，且达到本轮店铺级门槛（见 5.5，替代指南中旧的 1万/3万 电商门槛）；
3. 侵权方有赔付能力（企业优先，见 5.6）。

重复线索 = 同一侵权主体 + 同一侵权行为；已处理店铺不再重复上报。

## 2. 范围与边界
| | 本轮做 | 本轮不做 |
|---|---|---|
| 平台 | 淘宝/天猫、京东、1688 | 拼多多（后续阶段）、抖音/小红书等 |
| 采集 | 关键词搜索列表页；按条件抓详情页；主图下载 | 评论正文、直播、店铺主体工商深度溯源 |
| 判定 | 排除→文字分→视觉分→金额→店铺聚合→赔付能力标签→置信度 | 自动认定侵权（结论始终由人工复核） |
| 输出 | 每次运行的 Excel（线索汇总/链接明细/口径说明）、邮件报警 | Web 复核界面（后续）、自动写入 SaaS |
| 账号 | 试运行使用私人账号 | 专用账号（跑通后再商量） |

## 4. 整体流程
```
手动启动 → 登录态检查(每平台) ─失败→ 停该平台+邮件报警
  → 按 IP 关键词搜索列表页 → 字段解析/清洗 → 写商品表+当日快照表
  → 排除规则(白名单/正版/排除品类/已处理店铺)
  → 文字分 → [淘宝]文字过线才抓详情页取评论数
  → 主图下载+指纹 → 视觉分 → 综合分(仅排序)
  → 单链接金额 → 同平台+同店铺ID 当日聚合
  → [京东]店铺合计落在临界带才抓详情补字段 → 重新聚合
  → 门槛判断(>50万) → 赔付能力标签 → 置信度 → 生成线索(待复核)
  → 导出 Excel → 写运行日志 → 报警检查
人工：复核 → 已确认/驳回 → 录入SaaS后标记 已录入SaaS
```

## 5. 判定规则
所有配置键均指 `rules.example.yaml`。每条链接、每条线索都记录 `hit_reasons`（命中规则列表，格式 `规则键:命中词:分值`）。

| url | string | 是 | 规范化后的商品链接 |
| title | string | 是 | |
| shop_id | string | 是* | 缺失则 `shop_id_missing=true`，**不得用店铺名代替**；该链接不参与聚合，单列待人工补 |
| shop_name | string | 是 | 仅展示 |

### 5.1 排除（硬规则，命中即不进入线索，记录原因）
- 白名单：键 `平台+shop_id+IP`（`whitelist`），授权店铺直接排除。
- 正版信号：`exclude.genuine_keywords`（官方旗舰店、品牌授权、正版授权等）及 `exclude.genuine_shop_labels`（如京东自营、权利人官方店）。
- 排除品类：`exclude.categories`。
- 已处理店铺：状态为 已确认/已录入SaaS/驳回 的同 `平台+shop_id+IP`，已确认/已录入SaaS 的 90 天内不再上报（`dedup.suppress_days`），驳回的 30 天内不再上报（`dedup.suppress_days_rejected`）。
- 法律抗辩提示（不自动排除，加入 hit_reasons 供人工判断）：`legal_hints`（如书籍/评论/教学类可能合理使用）。

### 5.2 文字嫌疑分（0–100，截断）
按 `text_score.weights` 加减：目标 IP 词/别名(+45)、变体词(+12)、图案载体词(+16)、高发品类词(+10)、店铺白牌/工厂词(+6)、品牌官方词(−25)、正版信号(−55，若未在 5.1 排除)、仅命中其他 IP(−30)、目标 IP+蹭其他 IP(−18)、无任何 IP 词(−8)、标题过短(−20)。
等级：`>= text_score.level.high(60)` 高，`>= medium(35)` 中，否则低。
`need_vision`：无 IP 词、无正版信号、分数 ≥ `text_score.vision_rescue_min(12)` → 送视觉，不丢弃。
**淘宝详情页**：仅文字分 ≥ `fetch.taobao.detail_min_text_score`（默认=中线 35）或 need_vision 时抓详情页取评论数。

### 5.3 视觉分（主图，0–100）
主图与该 IP 官方参考图（`ips[].reference_images`）比对。`>= visual.confirm(70)` 视觉确认；`<= visual.reject(25)` 视觉排除；中间→人工。模型/方法由实现方决定，输出分数与理由写入 hit_reasons。同一 `image_phash` 复用历史视觉结果。

### 5.4 综合分（只影响排序与置信度，绝不影响金额）
`final = w_text×text + w_visual×visual`（`combined.w_text=0.45, w_visual=0.55`）；视觉确认时托底 `combined.floor_on_confirm=75`；视觉排除时封顶 `combined.cap_on_reject=35`；无视觉分时 final=text。
进入金额计算的链接：final ≥ `combined.min_final_score`(35)，或 need_vision 待人工。

### 5.5 金额
单链接：`估算销量 = min(销量, 评论数 × amount.comment_multiplier)`，倍数默认 10。
| 情形 | 计算 | 标记 |
|---|---|---|
| 销量、评论都有 | 单价 × min(销量, 评论×10) | — |
| 销量缺失（京东列表页常见） | 单价 × 评论×10 | `销量缺失` |
| 评论缺失、销量有 | 单价 × 销量 | `评论缺失,待核验`（`amount.on_comments_missing`） |
| 两者都缺/单价缺 | 0 | `待人工补齐` |
| 模糊值“1万+” | 用解析下限计算，保存原文 | 计算式注明 `按下限估算` |

计算式字符串示例：`29.90×min(10000[1万+按下限估算],1200×10)=299000.00`。金额保留 2 位小数。

店铺聚合：同 `platform + shop_id` 在**同一日快照**、当日在架的侵权链接金额求和（可跨该店多个委托 IP，Excel 中分列 IP）；**不跨日累计**、下架不计。
门槛：店铺合计 `> aggregate.shop_threshold`（500000 元）生成线索。
京东临界带：店铺合计落在 `[threshold×fetch.jd.near_band_low, threshold×near_band_high)`（默认 0.6–1.0）时，抓该店链接详情页补销量/评论后重算。

### 5.6 赔付能力标签（只打标签+排序，不做门槛）
`payment_ability.signals`：上市/国企、有投资机构股东、注册资本 ≥ 1000 万、有专利/APP、天猫店/皇冠店、店铺类型=企业。本轮可只实现平台可得的信号（店铺标签、类型），工商类信号预留字段，人工补。排序：企业 > 个体户 > 未知 > 个人。

### 5.7 置信度
线索置信度 = 链接综合分按金额加权平均，再按 `confidence.adjust` 增减（如存在缺失字段 −10、全部视觉确认 +10），截断 0–100；等级同 5.2 阈值。仅供复核排序。

## 6. 存储与状态（后端方案）
- 商品表 `products`：唯一键 `platform+product_id`；店铺、标题、主图本地路径、`image_phash`。
- 快照表（按运行日期） `product_snapshots`：日期、价格、销量原文/下限、评论原文/下限、在架、各分数、hit_reasons、金额、计算式。
- 线索表 `leads` 与链接表 `lead_links` 分离；线索状态：`待复核 → 已确认 / 驳回 → 已录入SaaS`。
- 每条线索/快照记录 `caliber_version` 与 `config_version`（配置文件 hash 或版本号）；历史不随配置变更重算。
- 白名单表、运行日志表 `run_logs`。

## 7. 登录与报警
- **运行环境（v0.3 变更，2026-11-05）**：服务器 IP 被平台风控（京东登录页二维码服务报错、淘宝试采 0 条），三平台采集改到 Xuan 的 Windows 本机，通过 CDP 驱动本机真实 Chrome 运行。
- 登录态：每平台单独保存一份登录状态（独立浏览器 profile，不导出 cookie）。Xuan 在本机各平台登录一次，之后爬虫复用。
- 登录判定：启动先检测；1688 必须拿到 `__cn_logon__` 才算登录成功。
- 试采：每平台关键词「奥特曼」1 词 × 1 页，报告各平台字段完整率（shop_id、sales_raw、comments_raw、shop_type 非空率，模糊值解析成功率）、京东价格非空率、1688 标题命中率、请求间隔日志，附原始样例。
- 采集通过 CDP 驱动本机 Chrome，登录态就是本机 Chrome 的用户数据目录（每平台一个）。
- 加密（v0.3）：profile 目录用 Windows EFS 加密，目录权限只给 Xuan 的 Windows 账号；SMTP 授权码存 Windows 凭据管理器，不落任何文件。取消 `security.profile_key_env`。
- 部署（R1）：数据库、运行入口、报警与采集同在 Xuan 的 Windows 本机。数据库用 SQLite，表结构按可迁移方式写，日后迁 PostgreSQL；不做每日定时：由 Xuan 自行选择时间手动启动（提供一键运行入口）。
- 每次运行结束仍写 `run_logs`；登录失效、采集量偏低照常邮件报警。不发每日汇总邮件。
- R1 终审必须有本机试采交付物（见上条试采报告），单测通过不等于采集可推行。
- 每次运行先检查登录（打开需登录的页面）；失效则**停止该平台**并发邮件报警，不强行抓取。
- 每次运行写 `run_logs`：平台、登录是否正常、采集条数、错误摘要、开始/结束时间。
- 报警只读 `run_logs`：登录失败，或采集条数 < `alert.min_items_per_platform` → 邮件。
- 发件邮箱：公司阿里邮箱 wuhengxuan@ip-sky.cn（SMTP smtp.qiye.aliyun.com:465 SSL，以实际为准）；授权码由 Xuan 在与后端与数据工程师的 1:1 中提供，加密存储。
- 节流：`crawl.rate_limit`，试运行用私人账号，量控制在配置上限内。

## 8. 输出：线索字段与 Excel
- 数据来源：Excel 模块只读后端提供的只读视图（`v_lead_summary`、`v_lead_links`），不直接读底层表，表结构调整不影响导出。
- 文件：`线索_YYYYMMDD.xlsx`，默认存放 `%USERPROFILE%\Documents\侵权线索\`（配置项 `export.dir`），同日重跑覆盖当日文件。
- 复核回写：Xuan 在 Excel 中填写「复核结论」「复核人」后，运行 `review.bat` 写回数据库线索状态，使已处理店铺的压制规则（90/30 天）生效。

缩略图宽约 80px，嵌入单元格；按 店铺类型优先级 → 置信度 → 金额 降序。

## 9. 验收标准
**金额用例**（倍数 10）：
| # | 输入 | 期望金额 | 期望标记/计算式 |
|---|---|---|---|
| A1 | 单价 50，销量 3000，评论 200 | 100000.00 | `50.00×min(3000,200×10)` |
| A2 | 单价 30，销量 500，评论 100 | 15000.00 | 取销量 500 |
| A3 | 京东 单价 99，销量缺失，评论 800 | 792000.00 | `销量缺失` |
| A4 | 单价 20，销量“1万+”，评论 2000 | 200000.00 | 下限 10000，含 `按下限估算` |
| A5 | 单价 20，销量 100，评论缺失 | 2000.00 | `评论缺失,待核验` |
| A6 | 单价缺失 | 0 | `待人工补齐` |

**聚合用例**：
- B1 同店（shop_id=S1）当日链接 300000 + 250000 → 550000，生成线索。
- B2 恰好 500000 → 不生成（严格大于）。
- B3 S1 昨日 300000、今日 250000 → 不生成（不跨日）。
- B4 两店同名不同 shop_id → 分开聚合。
- B5 shop_id 缺失 → 不参与聚合，标记 `店铺ID缺失`。
- B6 当日下架链接 → 不计入。
- B7 京东店铺合计 400000（在 0.6–1.0 带）→ 触发详情页补抓；200000 → 不触发。

**规则/流程用例**：
- C1 标题含“官方旗舰店 正版授权” → 排除，原因可见。
- C2 白名单 平台+shop_id+IP 命中 → 排除；同店其他 IP 不排除。
- C3 已录入SaaS 店铺次日不再出现在 Excel。
- C4 淘宝文字分 <35 且非 need_vision → 不抓详情页（日志可证）。
- C5 修改 `comment_multiplier` 为 5、门槛为 30 万，仅改 yaml 不改代码，结果随之变化，新记录 config_version 变化，旧记录不变。
- C6 视觉 80、文字 20 → 综合分 ≥75；视觉 10、文字 90 → ≤35；金额不变。
- C7 登录失效 → 该平台停止、收到报警邮件、run_logs 有记录；采集条数低于下限 → 报警。
- C8 同一 platform+product_id 重复采集 → 商品表一行，快照表每次运行（同日）一行。
- C9 Excel 两张主表+口径说明，缩略图可见、原图链接可点、复核结论/复核人为空列。
- C10 每条线索与链接 hit_reasons 非空。
