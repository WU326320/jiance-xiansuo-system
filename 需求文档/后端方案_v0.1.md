# 后端方案 v0.1（数据库 / 一键运行 / 去重 / 日志报警）
> 编写：后端与数据工程师 ｜ 2026-11-05 ｜ 依据：需求文档 v0.3（第 6、7 节）｜ 实现：dsh专家 ｜ 终审：代码验收
> 本文是规格，不含代码。尽量用成熟库，不自造轮子。

## 1. 部署与技术选型（第一轮）
- 全部运行在 Xuan 的 Windows 本机，与采集模块同一 Python 环境。
- 数据库：SQLite（开启 WAL），文件 `data/leads.db`。表结构用 SQLAlchemy 定义、Alembic 管迁移，不用 SQLite 专有语法，以后换 PostgreSQL 只改连接串。
- 配置：PyYAML 读 `rules.yaml`；主图指纹用 `imagehash`（pHash）+ Pillow；邮件用标准库 `smtplib`（SSL 465）；SMTP 授权码用 `keyring` 读 Windows 凭据管理器（服务名 `ip-lead-pipeline-smtp`，用户名为发件地址），任何文件里都不出现授权码。
- 不用任务计划程序，不发每日汇总邮件。

## 2. 一键运行入口
- 根目录 `run.bat`：双击即运行 `python -m pipeline run`，结束后窗口停留显示结果摘要（各平台条数、生成线索数、Excel 路径、是否有报警）。
- 可选参数：`--platform taobao,jd,1688`、`--dry-run`（不写库、不发邮件）。
- 单实例锁：`data/run.lock`，已有运行中则直接提示退出；异常退出后锁可自动失效（记录 PID，进程不存在即视为失效）。
- 运行前自动备份数据库到 `backups/leads_YYYYMMDD_HHMMSS.db`，保留最近 14 份。
- 流程：加载配置并登记版本 → 逐平台（登录检查 → 采集 → 入库）→ 判定 → 金额 → 聚合 → 生成线索 → 导出 Excel → 报警检查。**某个平台失败只停该平台，其他平台照常。**

## 3. 表结构
| 表 | 主要字段 | 唯一键 / 说明 |
|---|---|---|
| `config_versions` | config_version（yaml 内容 sha256 前 12 位）、caliber_version、yaml 全文、首次使用时间 | config_version |
| `shops` | platform、shop_id、shop_name、shop_type、shop_label_raw、更新时间 | platform+shop_id |
| `products` | platform、product_id、url、title、shop_id（可空）、shop_id_missing、main_image_url、image_path、image_phash、category、首次/最近采集时间 | platform+product_id |
| `product_snapshots` | product 外键、snapshot_date、crawled_at、run_id、ip_code、search_keyword、price、sales_raw/sales、comments_raw/comments、listed、text_score、visual_score、final_score、need_vision、hit_reasons(JSON)、amount、formula、missing_flags、config_version | product+snapshot_date（同日重跑覆盖更新，不新增） |
| `vision_cache` | image_phash、ip_code、visual_score、理由、config_version | image_phash+ip_code，同图复用 |
| `whitelist` | platform、shop_id、ip_code、备注、添加时间 | platform+shop_id+ip_code |
| `leads` | lead_no（平台-YYYYMMDD-####）、snapshot_date、platform、shop_id、total_amount、link_count、ip_codes、payment_tags、confidence、hit_summary、missing_flags、status（待复核/已确认/驳回/已录入SaaS）、review_result、reviewer、reviewed_at、saas_entered_at、caliber_version、config_version | platform+shop_id+snapshot_date |
| `lead_links` | lead 外键、snapshot 外键、ip_code、amount、formula | lead+snapshot |
| `lead_status_history` | lead 外键、旧状态、新状态、操作人、时间、备注 | 处理记录，只增不改 |
| `run_logs` | run_id、platform、stage、login_ok、items_count、error_summary、started_at、ended_at、status | 每次运行每平台一行，另有一行整体汇总 |

- 历史数据不随配置变更重算；每条快照和线索都记 config_version。
- 主图存到 `data/images/<phash前2位>/<phash>.jpg`，按指纹去重存一份。

## 4. 去重与压制
- 商品：platform+product_id 一行；快照：每商品每日一行（C8）。
- 线索：同一 platform+shop_id 同一快照日只有一条。
- 压制：在聚合前，按 platform+shop_id+ip_code 查 `leads`/`lead_links`：已确认或已录入SaaS 的 90 天内、驳回的 30 天内，相关链接不参与当天聚合，并在 hit_reasons 记录“已处理压制”。天数读配置 `dedup.suppress_days`、`dedup.suppress_days_rejected`。

## 5. 复核回写（让状态闭环，C3 依赖它）
- `review.bat`（`python -m pipeline review import <Excel路径>`）：读取 Excel「线索汇总」中的复核结论和复核人，按线索编号写回 `leads`，状态改为已确认/驳回，并写 `lead_status_history`。
- `python -m pipeline review mark-saas <线索编号...>`：标记已录入SaaS。
- 只认合法值（已确认/驳回），其他值跳过并在窗口提示。

## 6. 给 Excel 模块的只读视图（已与前端对齐，列名以此为准）
- 数据库路径配置键：`storage.db_path`，默认 `data/leads.db`（相对程序根目录）。Excel 模块用只读连接打开。
- 两个视图都只包含状态为「待复核」的线索，已被压制的店铺本来就不会生成线索；按日期过滤由导出侧用 `WHERE snapshot_date=?` 完成。
- 列名采用 `Excel导出方案_v0.1.md` §3.1 的建议（`leads.lead_no` 在视图里别名为 `lead_id`）。类型如下，金额与分数均为 REAL、保留 2 位小数，日期为 TEXT `YYYY-MM-DD`：

**v_lead_summary**：lead_id TEXT、snapshot_date TEXT、platform TEXT、shop_id TEXT、shop_name TEXT、shop_type TEXT、shop_label_raw TEXT、ip_codes TEXT（顿号拼接）、link_count INTEGER、shop_amount REAL、payment_ability TEXT、confidence REAL、hit_reasons_summary TEXT（非空）、missing_flags TEXT（可空）、review_result TEXT（空）、reviewer TEXT（空），另加排序辅助列 shop_type_rank INTEGER（企业1、个体户2、未知3、个人4）、caliber_version TEXT、config_version TEXT。视图自带 ORDER BY shop_type_rank, confidence DESC, shop_amount DESC。

**v_lead_links**：lead_id TEXT、snapshot_date TEXT、ip_code TEXT、product_id TEXT、image_path TEXT（可空）、main_image_url TEXT、title TEXT、url TEXT、price REAL、sales_raw TEXT、comments_raw TEXT、estimated_sales INTEGER、amount REAL、amount_formula TEXT、text_score REAL、visual_score REAL（可空）、final_score REAL、hit_reasons TEXT（非空，JSON 列表转成“；”拼接的文本）、missing_flags TEXT。

## 7. 日志与报警
- 文件日志：`logs/run_YYYYMMDD.log`，按天滚动，保留 30 天；每步记录开始/结束/条数/耗时。
- 报警只读本次运行的 `run_logs`：登录失败，或某平台 items_count < `alert.min_items_per_platform` → 发邮件。未捕获的异常和 Excel 导出失败也各发一封报警邮件。
- 发件人、收件人、SMTP 主机端口全部读配置；授权码只从凭据管理器读。邮件本身发送失败时写日志并在窗口提示，不影响主流程。
- 首次配置授权码：提供 `python -m pipeline setup-smtp`，交互输入（不回显）后写入凭据管理器；由 Xuan 自己在本机执行，授权码不经过任何聊天。

## 8. 验收（后端自测，交付时附结果）
1. 空库执行 `alembic upgrade head` 能建出全部表和两个视图。
2. 同一商品同日跑两次：products 1 行、当日快照 1 行；次日再跑：快照 2 行（C8）。
3. 线索回写后次日不再出现：已录入SaaS 90 天、驳回 30 天内被压制（C3）。
4. 改 yaml 后新记录 config_version 变化，旧记录不变（C5）。
5. 模拟登录失效：该平台停止、其他平台继续、run_logs 有记录、收到报警邮件（C7）；条数低于下限同样报警。
6. 双击两次 `run.bat`：第二次提示已在运行并退出。
7. 运行前自动生成数据库备份，超过 14 份自动清理。
8. 数据库和日志目录里搜不到授权码。
9. 第 9 节 B1–B7 聚合用例通过视图结果复核一致。
