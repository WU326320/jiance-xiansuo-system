# 采集模块方案 v0.1（淘宝/天猫、京东、1688）
> 编写：爬虫工程师 ｜ 2026-11-05 ｜ 依据：需求文档_v0.2（第 5.0、5.2、5.5、7 节）、site-analysis/summary-collect.md
> 实现：dsh专家（用 Scrapling，优先成熟插件）｜ 初验：爬虫工程师 ｜ 终审：代码验收

## 1. 结构
```
crawler/
  core/session.py     # 每平台一个持久化浏览器 profile 目录，Scrapling 有头/无头两种启动
  core/throttle.py    # 节流、每日上限
  core/retry.py       # 重试与错误分类
  core/parse.py       # 模糊数值解析（"1万+"→10000 等）、价格区间取最低、链接规范化
  core/schema.py      # 统一输出字段校验（pydantic），不合格的记为丢弃并写原因
  core/images.py      # 主图下载（带平台 Referer）+ 本地路径
  platforms/taobao.py | jd.py | ali1688.py   # 每平台一个模块，接口一致
  cli.py
```
每个平台模块实现同一接口：
- `check_login() -> bool`
- `search(keyword, max_pages) -> list[Item]`（列表页）
- `fetch_detail(product_ids) -> list[ItemPatch]`（详情页补字段，由判定模块按规则触发）

## 2. 运行方式（CLI）
- `python -m crawler login --platform taobao`：有头打开该平台 profile，供 Xuan 在 1:1 中手动登录一次。
- `python -m crawler run --platform taobao|jd|1688|all --config rules.yaml --date YYYY-MM-DD`：读配置里的 IP 关键词矩阵搜索，输出 `out/{date}/{platform}.jsonl` + 主图到 `out/{date}/images/`。
- `python -m crawler detail --platform taobao --ids-file ids.txt`：按 ID 补抓详情页，输出 `out/{date}/{platform}_detail.jsonl`。
- 每次运行结束写一条运行记录（JSON，字段见 6），供后端写入 `run_logs`。

## 3. 统一输出字段（每行一个 JSON，对齐需求文档 5.0）
platform, product_id, url, title, shop_id, shop_name, shop_label_raw, shop_type_raw_hint, price, price_raw, sales_raw, sales, comments_raw, comments, main_image_url, image_path, category, ip_code, search_keyword, page, rank, crawled_at, listed, flags[]
- 缺失一律 `null`，**不填 0**；flags 记 `销量缺失`/`评论缺失`/`店铺ID缺失`/`按下限估算` 等。
- shop_type 归一由判定模块按 `shop_type_mapping` 做，采集只给 `shop_label_raw`。
- product_id 解析失败 → 丢弃，计入运行记录 errors。

## 4. 各平台要点
**通用**：优先拦截页面加载时的接口 JSON 响应（浏览器网络响应监听）取数据，DOM 解析只做兜底，选择器集中放一个文件便于改版时修。以下接口/字段名以实测为准。

**淘宝/天猫**
- 搜索：`s.taobao.com/search?q=关键词&page=N`，数据来自 mtop 搜索接口响应。
- 取：商品 id、标题、价格、`X人付款`（sales_raw）、店铺名、店铺/卖家 ID、天猫标识（shop_label_raw）。
- 评论数列表页没有：只对判定模块回传的 ID 抓详情页（`item.taobao.com/item.htm?id=` / 天猫 `detail.tmall.com`）。
- 天猫与淘宝同一通道，platform 按标识填 tmall/taobao。

**京东**
- 搜索：`search.jd.com/Search?keyword=关键词&page=N`；每页后半部分靠下滑异步加载，必须滚动到底；价格也是异步加载，要等价格出现后再取（参考站点踩过"列表页无价格"的坑）。
- 取：SKU id、标题、价格、`X万+条评价`（comments_raw）、店铺名、店铺 ID（店铺链接 `mall.jd.com/index-{id}.html`）、自营/POP 标识。
- 销量：列表页没有，sales=null + flag `销量缺失`。
- 详情补抓（临界带 0.6–1.0 触发）：取精确评论数等。

**1688**
- 搜索：`s.1688.com/selloffer/offer_search.htm?keywords=关键词`，**中文关键词必须按 GBK 编码进 URL**。参考站点用 UTF-8 传中文导致出大量兜底商品，后来改用英文词，根子在编码；本方案用 GBK，并加校验：若结果标题命中关键词比例过低，记 warning。
- 取：offer id、标题、价格（区间取最低）、成交/已售（sales_raw）、公司名、实力商家/诚信通年限（shop_label_raw）。
- 店铺 ID（memberId 或 `shopXXX.1688.com`）、评论数列表页常缺：对进入金额计算的链接抓详情页补；仍缺则标记缺失。

## 5. 反爬、节流、重试
- 每平台串行、单浏览器上下文；平台之间可并行（配置开关，默认串行）。
- 节流（全部进配置 `crawl.rate_limit`）：翻页间隔随机 4–9 秒；关键词间隔 20–40 秒；每关键词最多 `max_pages`（默认 3）页；每平台每日最多请求数 `daily_max_pages`（试运行默认 150）；详情页间隔 6–12 秒。
- 错误分类：
  - 网络/超时/5xx → 指数退避重试最多 3 次（5s/15s/45s），仍失败记错误继续下一个。
  - 出现登录页 → 立即停止该平台，`login_ok=false`。
  - 出现滑块/验证码/"访问受限" → **不做自动破解**，立即停止该平台，记 `risk_blocked=true` 并保存截图，触发报警；当天不再重试该平台。
- 用私人号试跑，宁可少抓，不触发风控。

## 6. 登录与运行记录
- profile 目录：`{profiles_dir}/{platform}/`，权限 700，加密方式按后端方案。
- `check_login()`：打开需登录页（淘宝 `i.taobao.com/my_taobao.htm`、京东 `home.jd.com`、1688 `work.1688.com`），被重定向到登录页即判失效。
- 运行记录：platform, started_at, ended_at, login_ok, risk_blocked, keywords_done, pages_fetched, items_ok, items_dropped, drop_reasons{}, errors[], screenshot_path。

## 7. 日志
每次运行一个日志文件 `logs/{date}_{platform}.log`：每个请求记时间、URL、耗时、结果、条数；便于验证节流间隔和复现问题。

## 8. 初验标准（我验收，通过后交代码验收）
1. 三平台各用 2 个关键词 × 2 页实跑：product_id、title、price、url、main_image_url 完整率 ≥ 95%；给出各字段覆盖率表（尤其 shop_id、sales、comments）。
2. 模糊值单测：`1万+`→10000、`2.5万+`→25000、`300+`→300、`10万+人付款`→100000、`已售1000+件`→1000、`100+条评价`→100，都保留原文。
3. 1688 GBK：同一中文关键词，结果标题命中率明显高于 UTF-8（附对比）。
4. 京东：每页条数接近完整一页（验证下滑加载）、价格非空率 ≥ 95%。
5. 重复跑同一关键词：同一 platform+product_id 输出不产生重复行（单次运行内去重）。
6. 模拟登录失效（用空 profile）→ 平台停止、运行记录 login_ok=false。
7. 模拟风控页（本地假页面即可）→ 平台停止、risk_blocked=true、有截图、不重试。
8. 日志中翻页/关键词间隔符合配置。
9. 改 `max_pages`、间隔等只改配置即生效。
