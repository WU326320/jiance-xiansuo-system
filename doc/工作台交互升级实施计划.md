# 工作台交互升级实施计划

目标：简化线索复核和任务创建，沿用原生 HTML/CSS/JS、现有 API 与业务规则。

设计依据：用户已确认线索筛选、批量复核、任务创建、状态反馈、视觉层级和移动适配的渐进升级设计。

约束：不改数据库结构、采集判定逻辑、API 契约和正式端口 8765；不安装产品依赖，不提交代码；已有源码原位维护。

## 文件

- `workbench/web/app.js`：导航、异步请求、筛选与选择、复核、任务草稿和轮询。
- `workbench/web/style.css`：冷灰与蓝色操作色、独立风险色、控件状态、弹窗、响应式。
- `workbench/web/index.html`：导航语义、跳转入口和消息播报。
- `workbench/tests/conftest.py`：为测试线索补齐 run_id，与其快照保持一致。
- `utils/workbench-interactions.test.cjs`：Node 内置测试运行器的交互回归测试。
- `utils/workbench_preview.py`：临时数据库的本地验收服务器，隔离采集和邮件。
