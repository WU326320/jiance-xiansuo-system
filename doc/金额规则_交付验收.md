# 金额采集规则与交付验收

日期：2026-11-09。实施范围：`监测线索系统1.0`副本。

## 已实现口径

- `1万+`、`１万＋`按10000，保留原文及按下限估算标记。
- 明确券后价优先，普通区间价格取最低价；三平台列表和详情采用一致的字段优先级。
- 金额为 `P × min(S, C × 10)`，评论乘数固定10。三个字段均有效才能计算，真实零值有效。
- 缺失、非法或无法确定的字段保留原文和异常原因。未知金额在数据库为NULL、接口为null、页面为“待核验”、Excel金额单元格为空；真实零金额为0.00。
- 待核验商品保留明细，不计入有效金额小计；达到门槛的有效金额用于生成店铺线索。
- 使用Decimal计算并按ROUND_HALF_UP保留两位小数，超出金额列容量时转待核验。
- Excel保持十列：平台、IP、店铺名、标题、缩略图、商品链接、单价、销量、评论、总金额。计算说明与异常原因保存为金额单元格批注。
- 历史金额未批量重算。0011迁移允许金额为空并增加价格原文，0012补恢复已标记0011但缺失的临界店铺视图。

## 本轮修复

1. 导出集成夹具补齐视图依赖的eligible字段。
2. 京东不再使用布尔or回退价格，避免真实零价被其他价格覆盖；接口价格同步支持券后价优先。
3. 淘宝、京东、1688详情读取先寻找明确券后价、最终价、最低价，再寻找普通价格，避免原价先出现时覆盖券后价。
4. 旧库已有price_raw但金额列仍非空时也生成迁移前备份。
5. 重建金额视图时恢复临界店铺视图；对已经标记0011的数据库增加后续修复迁移。
6. 非法数值价格在采集模型中保留原文及待核验原因。

## 复验入口

在项目根目录运行：

```powershell
backend/.venv/Scripts/python.exe -X utf8 utils/verify_amount_accuracy.py
backend/.venv/Scripts/python.exe -X utf8 utils/verify_amount_accuracy.py --live-inventory
```

第一条只读读取所选历史JSONL，在临时目录创建隔离数据库进行浏览验收，更新doc中的核对CSV、截图、样表和JSON。第二条只读输出实际库版本、统计与完整性状态。

后端、采集与导出专项分别在对应子目录使用各自虚拟环境运行pytest。浏览器排序回放需按selected、unchanged、delayed_refresh场景分组，避免总执行时间超过工具时限。
