# 商品人工审核计算与导出

本轮新增 `project/backend/product_review.py`，复用项目已有 Python 技术路线，仅使用标准库。它提供显式口径校验、单商品金额计算及 CSV 导出，不启动前后端服务，不操作真实数据库，不访问网站。旧版店铺聚合、文字评分与缺失数据降级规则不适用于此模块。

## 尚待确认

- 目标网站、IP 名称、实际店铺白名单；白名单是否为空必须明确提供。
- 初始销售额恰好 500000 元是否进入详情采集：`inclusive` 包含，`exclusive` 不包含。
- 修正后是否再次过线：`keep_initial` 保留初始过线商品，`require_threshold` 再按相同边界筛选。
- 区间价：`review` 人工核查、`minimum` 最低价、`maximum` 最高价。多规格和带优惠条件的文本始终等待人工补齐；不能把最低规格当作实际成交单价。
- 缺失或不可解析数据：`review` 留作人工核查，`exclude` 标为异常排除；两者都保留审计行，不补零。
- “1万+”等模糊数量：`review` 人工核查，`lower_bound` 按下限估算并标注。
- 平台展示销量的时间窗口与指标含义需人工核验；付款人数、收货人数不转换为售出件数或评论数，而是保留原文、计算值留空并标注人数指标异常。`lower_bound` 只允许同一指标的模糊下限估算，不能授权人数与件数的转换。月销等未适配文案保留待人工核查。

没有用户确认不得将下面的合成测试配置用于真实业务；`policy_confirmed` 是调用方对确认结果的明确声明，不代表本轮已取得确认。

## 输入契约

只接受原始字符串 `price_raw`、`sales_raw`、`comments_raw`，从原文重新解析计算，避免历史解析器已取最低价格或已将缺失补零后失去可追溯性。采集器适配时必须提供这些原始值，不能把已有数值格式化后冒充原文。价格按人民币元计算；其他币种不得直接套用 50 万元门槛。

白名单使用 `platform + ip_name + shop_id`，无可比较的 ID 时才用店铺链接；双方 ID 均存在且不同，不通过链接或同名店铺排除。链接保留查询参数中的标识，忽略 fragment、参数顺序及末尾 `/`。不支持通过店铺名称排除，不推断 URL 别名或跨平台身份。

单商品同时保存原文、计算数值、初始销售额、修正销量、修正销售额、含时区的列表和详情采集时间、处理状态、白名单命中依据、完整口径与异常说明。审核结论和备注始终空白。商品缺少可用标识、链接或采集时间时无法成为正常候选。

初始金额过线且评论不可用的行输出 `needs_detail=true`；外部采集编排器可以据此决定补抓详情。只有评论数和销量都可用时才按 `min(销量, 评论数×10)` 修正，不使用评论推导缺失销量，也不使用展示销量代替缺失评论。比较使用未取整 Decimal 金额，导出显示四舍五入两位小数。

详情评论用于修正前，列表和详情时间必须均可解析且带时区，详情时间不得早于列表时间；比较实际时刻，跨时区同一时刻允许通过。缺失、无时区或倒序时保留原始时间与评论数，修正销量和修正金额留空，标注异常并输出 `needs_detail=true`。尚未确认缓存复用规则，因此不静默接受历史缓存评论。

## 合成输入示例

```json
{
  "ip_name": "测试IP",
  "platform": "test",
  "target_site": "https://example.com",
  "policy_confirmed": true,
  "policy": {
    "threshold_boundary": "inclusive",
    "corrected_filter": "keep_initial",
    "range_price": "review",
    "missing_data": "review",
    "ambiguous_counts": "review"
  },
  "whitelist": [],
  "products": [{
    "title": "测试商品",
    "url": "https://example.com/item/1",
    "shop_name": "测试店铺",
    "shop_id": "001",
    "shop_url": "https://example.com/shop/001",
    "price_raw": "￥500元",
    "sales_raw": "1000",
    "comments_raw": "80",
    "crawled_at": "2026-11-08T10:00:00+08:00",
    "detail_crawled_at": "2026-11-08T10:01:00+08:00"
  }]
}
```

在项目根目录执行（使用项目现有 Python 环境）：

```powershell
backend\.venv\Scripts\python.exe project/backend/product_review.py input.json output.csv
backend\.venv\Scripts\python.exe -m unittest discover -s project/backend -p "test_product_review.py" -v
```

CSV 为带 BOM 的 UTF-8，Excel 可打开；包含所有商品审计行，按“处理状态=人工审核候选”筛选即可查看候选清单。“待人工核查”和“异常排除”保留以防漏掉数据质量问题。所有候选仅供人工审核，不构成侵权认定。以公式字符开头的外部文本在 CSV 展示时添加单引号转义；输入原始记录保持不变。输出文件已存在时拒绝覆盖。

## 本轮交付边界

已实现计算函数接口与本地命令行导出。尚未接入现有工作台、数据库视图或真实网站采集器；未生成真实候选商品数据，未执行登录和详情页访问。实际接入前需先确认上述业务参数，再让采集器提供原始价格和详情评论时间；旧报表仍使用旧口径，不能当作本模块结果。
