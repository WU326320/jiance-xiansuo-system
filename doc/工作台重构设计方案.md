# 工作台重构设计方案 v1

状态：设计与独立原型，等待用户确认。未进入正式前端实施。

原型入口：[打开高保真可交互原型](../prototype/workbench-redesign.html)。下载整个项目后双击即可运行，无需安装依赖、启动服务或分配端口。

## 1. 调研范围与证据

本方案依据当前 `workbench/web/app.js` 全部页面渲染与事件处理、`style.css`、登录及初始化页面、任务服务限制进行梳理。问题中的尺寸来自 CSS 实际声明；尚未对真实业务数据进行用户可用性试验。原型以合成店铺与任务演示信息层级，数据不代表业务结果。

盘点覆盖 8 个工作页面（含个人账户），登录、邀请注册、首次初始化，以及复核、批量操作、任务详情、IP 编辑、公司白名单、邀请、账号权限、版本更新等弹窗。

## 2. 具体问题清单

| 编号 | 位置与证据 | 问题与影响 | 对应调整 |
|---|---|---|---|
| P01 | `style.css` 表头/徽章11px，`.small`/`.help`/表单标签12px | 小字承担日期、风险、说明、字段含义等实际工作信息；不是装饰文字 | 辅助最低14px，数据正文15px，表单15px，关键金额17px |
| P02 | 复核页：状态条、筛选卡、统计、九列表格纵向叠加 | 阅读开始前需要穿过多层容器；风险和进度统计同时争夺注意力 | 合并为单个工作面板；进度放标签，风险放筛选和行内 |
| P03 | `loadLeads()` 店铺下同时拼接IP、店铺类型、80字符命中摘要 | 行内技术规则重复出现，占用高度，影响店铺识别 | 店铺/IP/日期为摘要；命中、类型、编号进入详情 |
| P04 | 九列表格包含状态、复核人、日期等 | 当前标签已说明处理状态，重复列挤压店铺名和主操作 | 日期/复核人并入店铺辅助行；全部线索时补充行内状态 |
| P05 | 全金额显示两位小数，列宽固定压力 | 7位以上金额与其他字段竞争空间 | 列表以“万”缩写，悬停完整值；详情与导出保留完整金额 |
| P06 | 详情抽屉宽620px，多段纵向堆叠，底部复核区粘性定位 | 证据与判断无法并排，长详情需要反复滚动 | 桌面宽版详情左右分区；窄屏单列，保持清晰分节 |
| P07 | 任务页先完整表单+摘要，再显示九列任务记录 | 只查看已有任务也要经过创建界面；状态入口被推到下方 | 任务记录默认首屏，新建改为显著主按钮和专用弹窗 |
| P08 | 任务表格展开风险、邮件错误、开始/截止/完成时间 | 记录行密集，局部错误文本拉高整行 | 列表留任务、平台、状态、候选、创建时间；详细时间/风险/错误入详情 |
| P09 | IP行内编辑、公司白名单、停用三入口平铺；新建用prompt | 同级动作密集，交互样式割裂 | 统一“管理档案”入口，关键状态操作保留在管理页顶部；新建用标准表单 |
| P10 | 账号页邀请表单、邀请记录、账号表同时展开 | 低频表单占首屏，团队管理与邀请混排 | 团队/邀请双标签，生成邀请为主操作 |
| P11 | 生成邀请先填`invite-result`，随后立即调用`renderAccounts()` | 从事件顺序看，一次性邀请码可能被重绘清除，需正式阶段回归验证 | 原型以专用结果弹窗保留，关闭前不销毁；提供复制 |
| P12 | 系统设置所有字段常驻，“安全与任务”混合 | 查找字段需要遍历多个不相干概念 | 按邮件、安全、任务导出分区；跨分区保留会话编辑值 |
| P13 | 版本路径、平台状态、来源IP、邮件原因直接露出 | 技术字段与业务目标同权重 | 路径/状态明细折叠，错误详情按需展开；失败摘要保持可见 |
| P14 | 主导航平铺管理项与修改密码 | 每日业务与低频管理没有分组；账户设置语义分散 | 日常工作、业务管理、系统管理；个人账户置侧栏底部 |
| P15 | 小屏原表格最小宽800px，导航横向滚动 | 手机需要频繁横向滚动，关键操作可见性低 | 手机列表改语义卡片，菜单折叠，详情单列 |

## 3. 信息架构与入口迁移

不增加无数据支撑的总览首页。默认进入“线索复核”，直接处理待办。

```text
日常工作
 ├─ 线索复核 → 店铺证据 → 人工复核 / 连续复核
 └─ 运行任务 → 任务详情 / 新建采集 → 检查 → 确认运行
业务管理（管理员、主管）
 └─ IP / 白名单 → 管理档案 → 公司共享条目
系统管理（管理员、主管）
 ├─ 账号 / 邀请 → 团队 / 邀请记录
 ├─ 系统设置 → 邮件 / 安全 / 任务与导出
 ├─ 版本更新
 └─ 审计 / 邮件
个人账户（侧栏底部）→ 修改密码 / 退出
```

| 旧入口 | 新入口 | 原因与原任务如何完成 |
|---|---|---|
| 任务页首屏创建表单 | 页首“新建任务” | 查看任务优先；创建仅多一次显式点击，保留全部字段与会话草稿 |
| 详情底部复核 | 桌面详情右侧复核；手机证据之后 | 将判断与证据并置；保存后继续下一条，返回保留筛选和页码 |
| 常驻批量按钮 | 选中后操作条 → 确认弹窗 | 无选中时减少噪声；勾选后立即发现可执行动作 |
| IP行内三个按钮 | 管理档案 → 启停 / 编辑 / 公司共享 | 以对象集中管理；共享折叠标题显示数量，入口可发现 |
| 常驻生成邀请表单 | “生成邀请”弹窗 | 团队列表优先；生成后独立展示一次性结果 |
| 系统设置长页 | 三分区导航 | 全字段保留，减少同时阅读量；保存明确作用于当前分区 |
| 修改密码主导航项 | 侧栏个人信息按钮 | 符合账户操作语义；点击进入完整密码页 |
| 任务表邮件/风险/多时间列 | 任务详情 | 列表有状态与明确详情入口，失败有红色状态，详情展示原因 |

## 4. 核心流程

### 复核

待复核标签 → 常用筛选 → 店铺详情 → 查看金额、商品与命中依据 → 选择结论及复核人 → 保存 → 在当前筛选范围寻找下一条待复核。返回列表保留筛选、排序、分页；选中只作用于当前页。已录入SaaS不可再次提交。

多条误报仍保留现有“确认删除”输入校验，说明实际为误报标记，保留记录。原型暂不改服务端状态值与规则。

### 运行任务

任务记录 → 新建 → IP及模式 → 加载已有档案 → 平台 → 截止时间/提醒 → 可选高级设置 → 检查 → 运行摘要 → 确认。已有运行任务时阻止新启动，允许保留草稿；改变IP清空旧档案绑定；公司共享白名单只读。

任务详情 → 结果、失败原因、平台状态、邮件 → 下载本次报表。原型提供“演示完成”推进状态，此按钮不进入正式产品。

### 管理

IP列表 → 编辑 / 启停 / 添加共享条目；团队 → 权限/停用/临时密码；邀请 → 生成 → 复制一次性码 → 注册；设置 → 分区编辑与保存；更新 → ZIP选择 → 确认 → 结果 / 回滚；审计 → 详情。

## 5. 视觉规范

选择：深海军蓝导航、浅灰工作面板、单一蓝色主操作。导航与内容明确分区；以排版、留白、对齐建立层级，避免多色卡片和装饰图表。

| 规范 | 值与使用 |
|---|---|
| 字体 | 微软雅黑 / 苹方 / 系统无衬线；金额及编号采用Segoe UI等宽数字特性；不依赖在线字体 |
| 标题 | 页面28px/1.4；弹窗24px；分区20px；局部17px；移动页面26px |
| 正文 | 列表15px/1.65、字段15px、辅助14px；关键金额17px、详情金额27px |
| 颜色 | 背景`#f3f6fa`；正文`#192d45`；辅助`#586a80`；导航`#172d47`；主操作`#2c59c5` |
| 状态 | 达标/确认红色；待核验琥珀色；已录入/成功绿色；待复核/运行蓝色；总是同时提供文字 |
| 间距 | 4/8px基础步进；常用12/16/20/24/32/40px；桌面内容左右40px，手机16px |
| 组件 | 主按钮最小44px高；正文表单44px；面板14px圆角，控件8px；轻阴影与细边框 |
| 对齐 | 数字右对齐、店铺名左对齐、标签稳定、主要操作靠页首右侧；长字符串允许换行 |
| 聚焦 | 3px可见焦点环、跳过导航、语义表单、dialog焦点约束、Esc关闭、aria-live反馈 |
| 动效 | 160ms悬停与点击反馈、200ms提示进入；尊重减少动态效果偏好 |
| 状态反馈 | 查询刷新中、空筛选、无记录、日期错误、缺失必填、单任务冲突、成功反馈、结果保护、取消及危险动作确认 |

断点：大于1200为完整桌面；681–1200压缩侧栏和边距；900及以下列表卡片化、详情单列；680及以下折叠菜单、表单单列。验收以1440、768、390像素为主，补测320像素。

## 6. 原型使用与边界

- 双击 `prototype/workbench-redesign.html`，浏览器直接运行；建议先查看“原型导览”。
- 顶部可切换主管/管理员/普通用户；该工具条仅供设计评审，正式产品不保留。
- 所有记录均为合成演示数据，仅在内存中变更；刷新或点击“重置演示”恢复，不请求业务接口。
- 复核、筛选、分页、任务草稿、档案加载、白名单、邀请、角色、设置、密码校验、ZIP选择与回滚均有本地交互。
- 任务无真实自动采集或邮件，使用“演示完成”预览成功结果；失败任务也可查看错误。
- 商品证据使用文字演示，不关联真实商品；“查看来源”说明其来源状态，不虚构跳转。
- 下载提供明确标注的演示CSV，另链接已交付的单表Excel样表；CSV不冒充含图片的正式Excel。
- 登录/注册/初始化展示输入和流程，不执行身份验证；管理员视角限制邀请角色，普通用户隐藏管理模块。正式权限必须继续由后端校验。
- 系统设置分区保存需要在正式实施时将分区数据合并为现有接口字段，不能直接截断原PUT载荷。

## 7. 确认后实施与验收标准

当前只交付设计、原型与验收材料。用户确认视觉、导航、详情方式与任务入口后，再确认正式技术栈及服务端口，实施现有前端重构。

正式阶段按功能映射逐项回归：复核接口及已录入保护、状态值映射、日期/IP/规则搜索、分页/排序、下一条筛选范围、批量确认语义、任务提交/截止/轮询/并发限制/取消权限、IP白名单与公司共享、邀请码一次性结果与权限、全设置字段、文件下载边界、版本安装回滚、审计邮件字段、登录初始化及密码更新。

正式验收包括单元测试、接口测试和浏览器流程验证；原型阶段只验证本地模拟交互与静态资源，无业务API写入。原型验收不能替代正式业务回归。

原型浏览验证命令：`python utils/prototype_acceptance.py`。结果写入 `doc/工作台原型验收结果.json`，截图存于 `prototype/redesign-*.png`。
