# 淘宝漏补采修复与验收

日期：2026-11-10

目标：修复“保存后销量为空，但未发起详情补采”，覆盖新采集数据与同任务检查点恢复。

## 已确认的根因

- `crawler/crawler/core/parse.py::dedupe_items` 分别合并数值与原文，使有效销量与另一来源的促销文案混合；`model_copy(update=...)` 不重新运行字段校验。
- `crawler/crawler/runner.py::checkpoint` 创建了经过校验的 `Item`，但仍使用原始检查点字典筛选补采；最终保存却使用校验后的数据。
- 代表样本 `1085008955004`：原始 `sales=800`、`sales_raw=本月行业热销`，保存时销量被校验为空，却被原始非空销量排除补采。

## 修复边界

- 复用现有 Python / Pydantic / pytest，无新增依赖。
- 价格、销量、评论的数值和原文成对选择；有效值优先，真实零保留，不拼接不同来源的数字依据。
- 补采筛选使用与保存一致的校验结果；保持京东评论替代销量、淘宝额度、登录和风控处理规则。
- 不修改历史任务、生产数据和现有采集额度；测试输出使用临时目录。
