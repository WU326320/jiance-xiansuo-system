# 常规采集截止与补采收尾：修复及验收

日期：2026-11-10。范围：当前“监测线索系统1.0”副本。

## 结论与根因

原实现存在截止时间同时终止补采的问题。后端按距 `ends_at` 的剩余时间限制
采集子进程；详情补采调用链也检查 `CRAWLER_ENDS_AT`，后端部分详情处理到期后
直接跳过。因此截止时可能尚有补采未处理，却已经进入汇总、导出与通知。
工作台此前还在写入任务终态之前发送邮件，通知顺序需要一起修正。

历史问题任务 `WB20261110_121058_0011` 的日志显示，12:25:00 截止后立即入库，
12:25:01 开始汇总和导出。该日志仅证明当时很快进入结果处理，不能证明补采已完成。
本次没有修改或重新执行该历史任务，也不将本次回归当作历史数据已补齐的证据。

## 现在的完成条件

1. `ends_at` 保留原配置方式，含义明确为“常规采集截止时间”。
2. 到点不再发起新的常规采集；已经发出的请求完成解析、保存，并登记其产生的补采。
3. 补采在独立作用域中执行，排队、执行和既有有限重试都允许跨越常规截止时间。
4. 当前运行的补采全部处理为成功或最终失败后，才汇总、导出并提交整体任务终态。
5. 终态及结果已提交后，按既有收件人及邮件配置通知；补采等待期间不发完成邮件。
6. 重复执行同一运行中或终态任务被拒绝，避免重复执行导致重复通知。

保留单次请求超时、有限重试、补采额度、登录及风控规则；不引入无限重试。
有截止时间的常规采集由子进程自行停止新搜索并收尾，父进程不再在截止时强杀它。
独立详情进程不继承常规截止变量，但仍使用其配置的独立超时。

## 最终失败项

- 当前运行重试耗尽、额度限制或风控阻止继续处理的项目，记录原因并归入未解决项；
  不会在当前任务中无限重排，也不会仅因常规截止而取消仍有重试机会的项目。
- 成功字段与补丁保留并参与入库、重新评分和报表；独立详情超时同样保留当前已落盘补丁。
- 采集记录包含 `detail_failures`，持久进度保留 `detail_unresolved`；本轮待办收尾后清空。
- 存在最终失败时，平台/整体结果使用部分失败或失败状态，错误摘要带原因和相关标识；
  工作台详情和既有通知能看到失败信息，不将结果报告为全部成功。
- 邮件关闭或没有收件人时不发送；发送失败按现有规则记录邮件状态，不重新执行采集。
